# Spotnet 3.0.6.6: correct yEnc decoding of dot-stuffed articles

A single fix, but a serious one: every binary this client downloaded could come out subtly
corrupt. Anyone running 3.0.6.0 through 3.0.6.5 should upgrade and re-download anything that
finished with **Waarschuwing**.

## Fixed

- **Downloads were corrupted by the yEnc decoder.** Article bodies arrive from the news server
  still dot-stuffed: a line that begins with `.` is transmitted as `..` (RFC 3977 §3.1.1). In a
  yEnc body that happens whenever a line begins with payload byte `0x04`, because `0x04 + 42`
  is the character `.`. The decoder decoded both dots, so each such line inserted one extra byte
  and shifted everything after it within that segment.

  The result was a file a few bytes longer than the size its own yEnc header declares, failing
  its par2 hashes and unpacking with `packed data checksum error`. Repair could not compensate,
  because nothing was missing — the data on disk was simply wrong. Where a post ships only an
  index `.par2` with no recovery blocks, there was nothing to repair with at all.

  Whether a download survived depended on the poster: encoders that escape a leading `.`
  themselves never trigger server-side stuffing, and those posts decoded correctly. That is why
  the failure looked arbitrary, and why some spots worked while others from the same session
  did not.

  The 2.0 decoder this one replaced handled dot-stuffing; the managed rewrite introduced for
  3.0 did not. The slow fallback decoder always handled it, but it is only reached when the fast
  decoder throws, which it never did.

- The fallback decoder duplicated one byte when a line began with a `.` that the server had not
  stuffed. Only reachable against a non-compliant server, and it never ran in practice, but it
  was wrong.

## Upgrading

Files already on disk cannot be repaired — the corruption is in the bytes themselves. Delete and
re-queue anything that finished with a warning after installing this build.

## Verification

- **319/319 automated tests pass.**
- Five new decoder tests, including a synthetic article assembled the way a server sends one —
  yEnc headers, CRLF-terminated encoded lines, dot-stuffing and the terminating `.` line — decoded
  byte-for-byte by both the fast and the fallback decoder, plus a random 64 KB payload the two
  decoders must agree on.
- Confirmed the tests fail against the previous decoder.

Application version: **3.0.6.6**. This remains the community reconstruction based on Spotnet 2.0,
not an official upstream release.
